## 什么情况下会遇到

插件为了设代理或超时，依赖里带了自己的一份 undici。装上这个插件之后，宿主自己的模型请求、拉模型列表开始失败，卸掉插件就好了。

## 该怎么做

undici 在被 import 的那一刻，如果全局 dispatcher 还空着，就会把自己的 Agent 装上去。之后宿主自己的 undici（版本不同）拿到的是插件那份的 Agent，认不出是自己的，也就不再装自己的，于是请求出问题。

两件事：

- 插件发的每个请求都显式带上自己创建的 dispatcher，不依赖全局的。
- 不要调 `setGlobalDispatcher`。如果 import 时已经占了全局位置，照下面那个仓库的办法把它让出来。

## 证据

- 公开仓库：dshmarket 1.73.17 的 `src/net.ts`。注释记录了这个问题（它的 issue 861）：宿主在插件之后 import undici 时，拿到的是插件那份 undici 的 Agent，从而不再安装自己的，表现为宿主的模型请求和模型列表请求在插件加载后失败；注释里写了测量时的 Node 和两份 undici 的版本。它的处理是在 import 后把新版 undici 读取的那个全局位置清空，并让自己的每个请求都带上自建的 dispatcher。

## 还没核对的

这个仓库没有写明问题出现在哪个宿主版本上，这次也没有在 0.2.2-rc.1 上复现。具体要清哪个全局位置和 undici 的版本有关，照抄之前请读它的源码和注释。
