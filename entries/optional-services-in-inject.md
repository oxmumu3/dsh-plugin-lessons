分类: 接口与注册

## 什么情况下会遇到

插件用到某个不是处处都有的服务（比如只有桌面版才有的、或者另一个插件提供的）。在 `apply` 里直接 `ctx.某服务.xxx()`，换一个没有这个服务的环境，一启动就抛错。

## 该怎么做

把用到的服务写进插件的 `inject`。只在一部分逻辑里用到的，用 `ctx.inject(['服务名'], scope => { ... })` 把那部分包起来。

这样在没有这个服务的环境里，插件（或者那一部分）只是不激活，不会抛错连累别的东西。

## 证据

- 官方说明：0.2.2-rc.1 安装包内置的插件开发说明在稳定性一节写明，把可选服务放进 `inject` 或 `ctx.inject([...], ...)`，这样在没有这些服务的 profile 里插件保持不激活，而不是抛错。
- 公开仓库：dsh-agent-teams 0.1.29 的 `src/index.ts` 把网页服务当成可选的：按新旧两个服务名依次找，先尝试注册一次，再监听服务出现的事件，等它来了再注册，这样没有网页服务的环境里插件照样能启动。
- 宿主代码：0.2.2-rc.1 宿主自己的插件管理器就是这么用的，它用 `ctx.inject(['connection'], scope => ...)` 包住注册 HTTP 路由的那一段。
