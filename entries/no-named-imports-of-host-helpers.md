分类: 发版与兼容
状态: 有效
宿主版本: 0.1.2-alpha.1
最近核对: 2026-11-10
来源: 社区插件拆解（2026-11-10）

## 什么情况下会遇到

宿主的某个包导出了几个方便的辅助函数，插件直接 `import { 某函数 } from '@deepseek-ai/dsh-某包'`。宿主下个版本把这个导出删了。

## 该怎么做

「服务不在」和「导出不在」后果完全不同：

- 服务不在：写在 `inject` 里的话，插件只是安静地不启动。
- 具名导出不在：模块求值时就是一个 `SyntaxError`，加载器把它当成入口失败，宿主直接退出。装了你的插件，整个宿主起不来。

所以只依赖服务本身。辅助函数做的事自己写几行内联进来。服务的方法在不同版本间有变化的，用 `typeof service.某方法 === 'function'` 判断，没有就降级并记一条日志。

## 证据

- 公开仓库：dshmarket 1.73.17 的 `src/settings.ts`。文件注释记录了这次事故：它原来从宿主的设置包里引入两个辅助函数，宿主 0.1.2-alpha.1 把它们删了，报 `SyntaxError: The requested module ... does not provide an export named ...`，装上这个插件宿主就完全起不来；注释还说明了服务本身在那前后并没有变，只是包装函数没了。现在的代码内联了包装函数做的事，并用 `typeof ... register === 'function'` 判断。
