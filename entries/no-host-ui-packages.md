## 什么情况下会遇到

想让插件界面和宿主长得一样，于是直接 `require('@deepseek-ai/dsh-client-ui-primitives')`，拿宿主的按钮、弹窗来用。

## 该怎么做

不要把宿主的任何 Client 包当模块加载。这些包没有稳定承诺，升级时说变就变；组件一抛错，你的整个展位入口就空了，控制台会出现 `slot entry crashed in '<展位名>'`。

想长得像宿主：照着宿主控件的结构和样式自己写一份，类名加上自己插件的前缀，颜色只引用 `--dsw-alias-*` 变量，并保留用户已经习惯的行为（弹窗的焦点和 Esc 关闭、开关的 `role="switch"`）。

清单的 `dsh.client.inject` 里列宿主包名没有问题，那只是声明加载顺序。

## 证据

- 官方说明：0.2.2-rc.1 内置的插件开发说明在界面一节明确不让 require 这个包或加载其他宿主 Client 包，理由是它们会不打招呼地变，而纯 JS 插件没有类型检查兜底。
- 经验做法：「发现好插件」内置清单里的原话是「不引用宿主内部 UI 包」。

## 备注

社区里有插件把这类包写进 `peerDependencies` 并且能运行。所以这条的意思不是「用了就装不上」，而是「宿主一升级就可能坏」。
